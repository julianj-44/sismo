=====================================================================
PASO A PASO: CONECTAR POSTGRESQL A CLAUDE CODE (MCP)
=====================================================================
Requisitos: PostgreSQL corriendo (localhost:5432), pgAdmin, Node.js y
Claude Code instalados.


---------------------------------------------------------------------
1. CREAR EL USUARIO DE SOLO LECTURA
---------------------------------------------------------------------
En pgAdmin (Query Tool), primero revisa si ya existe:

  SELECT rolname FROM pg_roles WHERE rolname = 'claude_ro';

Si sale vacio, crealo. Usa una clave solo con letras y numeros (simbolos
como @ # / : rompen la URL):

  CREATE ROLE claude_ro LOGIN PASSWORD 'CLAVE_SOLO_LETRAS_Y_NUMEROS';


---------------------------------------------------------------------
2. DAR PERMISOS EN LA BASE
---------------------------------------------------------------------
Abre la Query Tool CONECTADA A LA BASE DEL PROYECTO (no a "postgres").
Cambia MI_BASE y MI_ESQUEMA (por defecto el esquema es "public"):

  GRANT CONNECT ON DATABASE MI_BASE TO claude_ro;
  GRANT USAGE ON SCHEMA MI_ESQUEMA TO claude_ro;
  GRANT SELECT ON ALL TABLES IN SCHEMA MI_ESQUEMA TO claude_ro;
  ALTER DEFAULT PRIVILEGES IN SCHEMA MI_ESQUEMA
    GRANT SELECT ON TABLES TO claude_ro;

La ultima instruccion incluye tambien las tablas que crees en el futuro.

Si tu PostgreSQL es version 14 o menor, agrega por seguridad:

  REVOKE CREATE ON SCHEMA public FROM PUBLIC;


---------------------------------------------------------------------
3. REGISTRAR LA CONEXION (PowerShell)
---------------------------------------------------------------------
Ejecuta DENTRO de la carpeta del proyecto:

  cd "RUTA_DE_LA_CARPETA"
  claude mcp add --scope local postgres -- cmd /c npx -y @modelcontextprotocol/server-postgres postgresql://claude_ro:CLAVE@localhost:5432/MI_BASE

El alcance "local" guarda la conexion fuera del repo: la clave NO se
sube a GitHub.


---------------------------------------------------------------------
4. VERIFICAR
---------------------------------------------------------------------
En la misma carpeta:

  claude mcp get postgres

Debe mostrar: Scope: Local config y Status: Connected.

Abre Claude con:

  claude

(si ya estaba abierto, cierralo y abrelo de nuevo). Dentro escribe:

  /mcp

Debe aparecer "postgres" con una palomita verde.


---------------------------------------------------------------------
5. PROBAR
---------------------------------------------------------------------
1) Pidele: "lista las tablas y vistas que puedes leer".
   Debe responder con ellas.

2) Pidele: "crea una tabla de prueba".
   Debe fallar con "permission denied". Si la crea, el usuario tiene
   mas permisos de los debidos.


---------------------------------------------------------------------
SI DICE QUE NO HAY TABLAS
---------------------------------------------------------------------
Casi siempre es el esquema. Los permisos se dan por esquema, y "public"
es solo el nombre del esquema por defecto (no significa "publico").
Conectado con tu usuario de administracion, busca donde estan tus tablas:

  SELECT schemaname, tablename FROM pg_tables
  WHERE schemaname NOT IN ('pg_catalog','information_schema');

Luego repite los GRANT del paso 2 con ese esquema.


---------------------------------------------------------------------
COMANDOS UTILES
---------------------------------------------------------------------
  claude mcp list                       ver servidores y su estado
  claude mcp get postgres               detalle de la conexion
  claude mcp remove postgres -s local   quitar la conexion del proyecto

Cambiar la clave: primero en PostgreSQL

  ALTER ROLE claude_ro PASSWORD 'NUEVA_CLAVE';

luego quitar el MCP y repetir el paso 3.


---------------------------------------------------------------------
SEGURIDAD
---------------------------------------------------------------------
- Nunca uses el usuario "postgres" para Claude: es superusuario.
- No compartas capturas donde se vea la clave dentro del comando.
- No guardes el comando con la clave dentro del repo de GitHub.
- Usa una base por proyecto; no dejes un servidor "postgres" en alcance
  user, porque se veria en todos los proyectos.
- Si pbi_lector (Power BI) se usa en la conexion de Claude, los permisos
  que le des a Claude tambien los recibe Power BI. Con claude_ro quedan
  separados.
